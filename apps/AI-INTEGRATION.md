# AI framework integration

Framework source and version locks belong to the parent workspace:

- `software/MNN`: MNN, AME kernels and the shared allocator.
- `software/ncnn`: NCNN and XSAI convolution glue.
- `software/llama.cpp`: llama.cpp and ggml.

`apps/{mnn,ncnn,llama.cpp}` contain only build/install wrappers, harnesses
and tests. `source-ready` and the legacy `repo` target validate inputs;
they never clone sources or choose an app-local `repo/` fallback.
Use `MNN_SRC`, `NCNN_SRC`, or `LLAMA_CPP_SRC` explicitly for another checkout.
`*_HOME` remain legacy aliases; `*_SRC` take precedence. NCNN and llama.cpp
also require the selected MNN tree's allocator/kernel files.

Use `source env.sh` in the parent workspace. Initialize the three software
submodules before building. For a standalone rootfs worktree, set
`XSAI_ENV_ROOT=/path/to/xsai-env` and `RISCV_ROOTFS_HOME=/path/to/rootfs`;
these point to shared sources/toolchains and this worktree's install area.

The default image remains the existing llama workload, including
`test-backend-ops` and the tracked metadata-only `.gguf.om` fixtures.
`llama-model.gguf` is generated by the existing `prepare-model` pipeline;
real inference models are distinct from metadata-only fake benchmarks.
No local BF16/SqueezeNet/NCNN model cache is required by the default image.

## Opt-in MNN / NCNN images

From the parent workspace:

```sh
source env.sh
make firmware XSAI_ROOTFS_EXTRA_APPS=mnn XSAI_WORKLOAD=mnn-smoke \
  INITRAMFS_SOURCE="$RISCV_ROOTFS_HOME/rootfsimg/initramfs-disk-xsai.txt $RISCV_ROOTFS_HOME/rootfsimg/initramfs-xsai-mnn.txt"
make firmware XSAI_ROOTFS_EXTRA_APPS=ncnn XSAI_WORKLOAD=ncnn-smoke \
  INITRAMFS_SOURCE="$RISCV_ROOTFS_HOME/rootfsimg/initramfs-disk-xsai.txt $RISCV_ROOTFS_HOME/rootfsimg/initramfs-xsai-ncnn.txt"
```

MNN installs only the MobileNet int8 smoke inputs via its explicit model pipeline.
It needs host conversion tools and Python Pillow for sample-image inputs.
Supply `ONNX_FILE=/path/to/mobilenetv2-12.onnx` and
`MOBILENET_V2_ONNX_SHA256=<sha256>`; alternatively supply a fixed
`MOBILENET_V2_ONNX_URL` plus the hash. Unspecified or mismatched hashes fail.
`make -C apps/mnn install-binaries` is a model-free build/install gate.
`XSAI_MNN_EXPECTED_ARGMAX` is an optional assertion for a known model/input;
there is no universal hardcoded label for custom model or calibration inputs.
Use app-local fp32/int8 comparison for numerical validation.

NCNN's install and self-contained differential smoke need no model downloads.
External end-to-end models are an explicit optional input, not an implicit
cached prerequisite. `XSAI_NCNN_TEST=1` adds the official convolution suite.
Neither MNN nor NCNN runs automatically as part of the default llama workload.

Validate apps locally before full firmware boot. In particular:

```sh
make -C firmware/riscv-rootfs/apps/mnn source-ready
make -C firmware/riscv-rootfs/apps/ncnn source-ready
make -C firmware/riscv-rootfs/apps/llama.cpp source-ready
bash firmware/riscv-rootfs/apps/llama.cpp/tests/test-source-selection.sh
```

Generated binaries, conversion outputs, calibration tensors and model caches
stay untracked. Do not publish a manifest entry unless a tracked input or
an explicit build/install rule provides it.

After building, verify the exact descriptors before packing:

```sh
make -C firmware/riscv-rootfs verify-manifest \
  ROOTFS_MANIFESTS="rootfsimg/initramfs-disk-xsai.txt rootfsimg/initramfs-xsai-mnn.txt rootfsimg/initramfs-xsai-ncnn.txt"
```
